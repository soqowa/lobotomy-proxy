# Proxy Guard для macOS

Приложение направляет выбранный веб-трафик в HTTP-, HTTPS- или SOCKS5-прокси. Поддерживаются macOS 14 и новее, Apple Silicon и Intel. Параметры входа хранятся в Связке ключей пользователя.

## Скачать приложение

В [последнем релизе GitHub](https://github.com/soqowa/proxy-guard/releases/latest) скачайте ZIP для macOS, распакуйте его и перенесите **Proxy Guard.app** в папку «Программы». Один архив подходит для Intel и Apple Silicon. Для доступа войдите в GitHub под аккаунтом с доступом к репозиторию. Тип подписи указан в описании конкретной версии.

При необходимости скачайте рядом с архивом `SHA256SUMS.txt` и запустите в этой папке `shasum -a 256 -c SHA256SUMS.txt`.

## Первое подключение

1. В **Подключении** укажите протокол, сервер, порт и учётные данные. Нажмите **Проверить и сохранить**. Проверка через прокси сверяет выход по двум сервисам. В режиме **Берлин · CryptoStorm** укажите числовой IP прокси. Приложение отправляет DNS-запросы через прокси по HTTPS и подключается к полученным IP. При ошибке DNS запрос блокируется. [Резолвер CryptoStorm](https://cryptostorm.is/blog/doh)
2. В **Фильтре** добавьте домены вручную или выберите несколько пресетов. При отключении пресета сохраняются ручные записи и домены остальных пресетов. Каждая запись охватывает поддомены.
3. Добавьте приложения, весь поддерживаемый веб-трафик которых должен идти через прокси. Черновик сохраняется при редактировании. Приложения прежней версии переводятся на режим для всех сайтов при следующем обновлении профиля.
4. Нажмите **Обновить профиль → Открыть настройки системы**. macOS может запросить права администратора для локальной службы и DNS. В **Основные → Управление устройством** подтвердите профиль **Proxy Guard · Фильтр**. После подтверждения настроек передача запускается автоматически. Пока идёт обновление, применяются доступные системные правила соответствующей версии. Если служба не может подтвердить новую конфигурацию, её обработчик держит передачу закрытой.
5. На экране **Обзор** показаны причины, мешающие передаче. Каждая строка ведёт к нужной настройке. Профиль включает домен ip.net.coffee и его случайные тестовые поддомены. В поддерживаемом браузере по умолчанию можно проверить DNS из обычного окна. Блок **Проверка утечек** открывает полную проверку Net.Coffee в выбранном защищённом браузере после подготовки его запуска. Проверяйте результаты DNS, WebRTC/UDP и пояс непосредственно в этом окне. [Проверка Net.Coffee](https://ip.net.coffee/claude/)

## Часовой пояс

Приложения из применённого фильтра получают переменную TZ с подтверждённым поясом прокси. Фоновая служба отслеживает обычный запуск из Finder и Dock. Если экземпляр запущен без управляемого окружения, служба просит его штатно завершиться и открывает заново с TZ. Сохраните документы перед установкой профиля. При отказе приложения выйти, нескольких одновременно запущенных экземплярах или неподтверждённом запуске его прокси остаётся закрытым. При следующем открытии из Dock процедура повторяется. Приложения по-разному используют TZ. Браузер с собственными настройками приватности может показывать другой пояс.

**Подключение → Часовой пояс → Применить к Mac** отдельно меняет системный пояс. **Откатить пояс** восстанавливает сохранённое значение с проверкой на последующий ручной выбор пользователя. Запись о смене системного пояса сохраняется и после удаления фильтра.

## Маршрутизация и откат

Общие доменные правила используют локальный split DNS, секцию hosts и проверку имени TLS на порту 443. Chrome, Edge, Brave, Arc, Vivaldi и Firefox получают обязательные настройки браузера. У выбранного приложения фиксированный локальный прокси. Остальные поддерживаемые браузеры получают PAC для общих доменов. Safari использует системный DNS. Для настольного клиента с egressProxyUrl поддержка определяется его режимом. Прямые сокеты, виртуальные машины, некоторые обновления, сторонний DoH и VPN с собственными маршрутами могут обходить настройки совместимых клиентов. Прошедший тест относится к конкретному окну и сетевой конфигурации.

**Фильтр → Откатить профиль** останавливает обработчик и удаляет принадлежащие Proxy Guard сетевые правила, службу и профиль. Перезапустите затронутые приложения. Черновик и данные подключения сохраняются для повторного применения.

## Сборка и проверки

Из каталога проекта запустите `./build.sh`. Требуются Xcode и Go. Сборка по умолчанию записывается в **Deliverables/Proxy Guard.app**. Для распространения на другие Mac с проверкой Gatekeeper нужны Developer ID и нотарификация.

- `(cd engine && go test -race ./... && go vet ./...)` проверяет прокси, доменные правила, допуск приложения, отказы и восстановление настроек.
- `python3 Tests/profile.py` проверяет пресеты, формат профиля и определение состояния.
- `python3 Tests/zone-launch.py` запускает временное тестовое приложение обычным способом, затем проверяет управляемый перезапуск, TZ и блокировку до подтверждения.
- `node Tests/chrome-route.cjs` проверяет отключённый прокси на локальных адресах. Требуется playwright-core и полный Chromium. Путь к нему можно задать в PG_TEST_CHROMIUM.
- `node Tests/net-coffee.cjs` запускает живой браузерный тест через явно указанный тестовый локальный канал PG_DIAGNOSTIC_PROXY и пояс PG_TEST_ZONE. PG_TEST_DNS_COUNTRY и PG_TEST_DNS_CITY задают ожидаемую страну и город всех обнаруженных резолверов. На обычном рабочем Mac для текущего профиля используйте кнопку в **Обзоре**.

## Выпуск версии

Проверки в GitHub Actions запускаются для изменений в `main` и pull request. На macOS выполняются тесты Go с проверкой гонок, `go vet`, тест профиля и сборка Universal для двух архитектур.

1. Обновите файл `VERSION`, зафиксируйте изменения и отправьте их в `main`. Проверьте результат CI.
2. На Mac с Xcode, Go, GitHub CLI и сертификатом подписи запустите `./scripts/release.sh`. Скрипт собирает приложение, создаёт тег, загружает ZIP и SHA-256 и публикует релиз. Закрытый ключ используется локально через Связку ключей.
3. Для публикации уже проверенного ZIP той же версии передайте его путь аргументом, например `./scripts/release.sh "../Deliverables/Proxy Guard macOS.zip"`. Для нотарифицированного релиза передайте заранее нотарифицированную сборку со вложенным билетом. Для собственных заметок задайте `RELEASE_NOTES_FILE` с путём к Markdown-файлу.

`PROXYGUARD_SIGNING_IDENTITY` позволяет выбрать сертификат явно. По умолчанию скрипт сначала ищет Developer ID Application, затем Apple Development.
